## 快速开始

1. 进入 `Release\` 目录，双击 **`PSBatteryTray.exe`**。
2. 程序**没有主窗口**，启动后直接进入系统托盘。
3. 把手柄通过 USB 或蓝牙连接到电脑，托盘图标会自动开始显示电量。

> **首次运行看不到图标？**
> Windows 10 默认会把新程序的托盘图标折叠进任务栏左侧的
> **"隐藏的图标"面板（⌃）**。点击那个小箭头就能看到它，
> 然后用鼠标把它**拖到任务栏上**即可固定常驻。这是 Windows 的默认
> 行为，不是程序缺陷。

**停止程序**：右键托盘图标 → **退出**。
（程序不驻留任何服务，退出即彻底结束，不会留后台进程。）

## 支持的设备

索尼的 USB Vendor ID 固定为 `0x054C`。

| 手柄 | PID | 电量读取 | 备注 |
|---|---|---|---|
| **DualShock 4** (CUH-ZCT1) | `0x05C4` | ✅ | PS4 第一代 |
| **DualShock 4** (CUH-ZCT2) | `0x09CC` | ✅ | PS4 第二代 / PS4 Pro 附带 |
| **DualShock 4 无线适配器** (CUH-ZWA1) | `0x0BA0` | ✅ | 官方 USB 适配器，原样转发 DS4 报告 |
| **DualSense** | `0x0CE6` | ✅ | PS5 标配 |
| **DualSense Edge** | `0x0DF2` | ✅ | PS5 精英手柄 |
| DualShock 3 | `0x0268` | ❌ | 能识别，但协议不含电量，界面标注"不支持" |
| PS Move 控制器 | `0x03D5` | ❌ | 同上 |

- **USB 与蓝牙都支持**，见 [USB 与蓝牙](#usb-与蓝牙)。
- 支持**多手柄同时连接**：菜单会全部列出，托盘图标显示**电量最低的那一个**。
- 手柄**热插拔自动识别**：插上/拔掉/断连重连都会被检测到，无需重启程序。

## 数据来源与精度说明

### 数据来源

程序**直接读取手柄的 HID 输入报告**（Input Report），这是手柄主动、
周期性推送的原始数据。字节偏移逐条对照 Linux 内核驱动
`drivers/hid/hid-playstation.c`（由索尼工程师参与维护，是事实上的公开协议规范）。

| 手柄 | 连接 | 报告 ID | 报告长度 | 电量字节下标 |
|---|---|---|---|---|
| DualShock 4 | USB | `0x01` | 64 | **30** |
| DualShock 4 | 蓝牙 | `0x11` | 78 | **32** |
| DualShock 4 | 蓝牙（精简） | `0x01` | 10 | **无**（协议不含电量字段） |
| DualSense | USB | `0x01` | 64 | **53** |
| DualSense | 蓝牙 | `0x31` | 78 | **54** |

> 为什么不走 XInput？
> `XInputGetBatteryInformation` 只对 **Xbox** 手柄有效；`XINPUT_GAMEPAD`
> 结构体里根本就没有电池字段，对 PS 手柄一律返回 0。所以必须绕过 XInput，
> 直接读 HID 报告。

### 精度限制（请务必了解）

**PS4 / PS5 手柄只上报约 11 个电量档位，每档 10%。**
这是手柄固件与 HID 协议的物理上限，不存在任何能读取 1% 精度的
公开方案。

- 原始等级为 `0 ~ 10`（DualSense 驱动注释原文：
  `0 = 0-9%, 1 = 10-19%, .. and 10 = 100%`）；
- 本程序**原样保留**这个等级（界面上的"**等级 7/10**"），
  百分比只是按与 Linux 驱动一致的**区间中点**换算：

  ```
  等级 0 → 5%    等级 5 → 55%    等级 10 → 100%
  等级 1 → 15%   等级 6 → 65%
  ```

- 因此界面上的百分比**一律带"约"字**（例如"约 75%"），
  并且在提示里同时给出等级，让你清楚知道这是估算而非精确读数。

**本程序绝不伪造精度。** 你不会看到"73%"这种数字 —— 因为手柄根本
给不出。

### 异常值的处理

手柄可能上报"电压超范围""温度异常""充电错误"等状态。此时程序显示
**"电量未知 / 状态异常"**，而**不是**显示 0%。
（Linux 内核驱动在这些情况下会把电量置 0，本程序刻意不这样做 ——
否则你会收到一次虚假的"电量耗尽"告警。）

## USB 与蓝牙

**两种连接方式都完整支持**，但底层报告格式不同，程序会自动识别：

| | USB | 蓝牙 |
|---|---|---|
| 报告 ID | DS4 `0x01` / DualSense `0x01` | DS4 `0x11` / DualSense `0x31` |
| 报告长度 | 64 字节 | 78 字节 |
| 电量字节位置 | 与蓝牙不同（见上表） | 与 USB 不同 |
| 供电 | 有线供电，通常同时充电 | 电池供电 |

### DS4 蓝牙的一个特殊情况

部分系统上，DualShock 4 通过蓝牙连接时 Windows 只让它发送 **10 字节的
"精简报告"**，该报告**协议层面就没有电量字段**。

程序的处理：

1. 先尝试发送特性报告（Feature Report）请求手柄切换到**完整报告模式**；
2. 若切换成功 → 正常显示电量；
3. 若切换失败 → 菜单中该项显示 **"⚠ 电量未知"**，并在详情里说明原因，
   **不会显示虚假数字**；日志里会记录原始报告十六进制，便于排查。

> 如果遇到这种情况，把 DS4 改用 USB 连接，或改用 DualSense，均可正常读数。

### 充电状态

- **DualSense**：协议直接提供充电状态（放电 / 充电中 / 已充满 / 异常）。
  图标与菜单会显示 `⚡ 充电中` 等标记。
- **DualShock 4**：只有"是否插入 USB 线"这一位（`bit 4`）。插入线时视为
  充电中，容量达到 `11` 视为已充满。

## 托盘图标规则

### 图形结构

图标按 **Windows 10 扁平单色**风格自绘：直角矩形、无渐变、无阴影、无圆角、
无羽化过渡，纯白（深色任务栏）或纯黑（浅色任务栏），与系统图标视觉语言统一。

基准网格 **16 格宽 × 10 格高**（1080P / 100% 缩放下的 16×10 像素）：

```
      +-------------------------+         外框 14×10，线宽 1 格
      |                         |
      |    +---------------+    |  +--+   正极 2×4，垂直居中
      |    |  电量块 10×6  |    |  |  |
      |    +---------------+    |  +--+
      +-------------------------+
```

| 部位 | 尺寸 / 位置 |
|---|---|
| 整体字形 | **16 × 10 格** |
| 外框 | 14 × 10 格，线宽 **1 格** |
| 内腔 | 12 × 8 格（外框减去线宽） |
| 电量块 | 10 × 6 格 |
| 正极凸起 | 2 × 4 格，垂直居中 |

**关键点**：电量块与外框之间有一圈 **1 格宽的连续留白**（电量块相对内腔四周
各内缩 1 格）。这不是"在电量条中间画一条线"，而是**整个电量区域向内缩进**，
与外框之间形成四周等宽的间隔；电量块本身仍是纯实心几何形状。

电量块满格 10 格宽，**横向 1 格 = 10%**，与手柄的 11 档电量天然一一对应。

### 清晰度（小尺寸锐利像素风）

托盘图标最终只有 16~32 **物理**像素，所以「清晰」只有一条路：**不做任何重采样**。
本程序从两层同时保证这一点。

**第一层：按目标像素尺寸直接算几何（不缩放图片）**

- 尺寸取自 `GetSystemMetrics(SM_CXSMICON)`，随系统 DPI 变化
  （100% → 16px、125% → 20px、150% → 24px、200% → 32px）；
- 几何**直接在目标像素网格上计算**：外框线宽取
  `sw = round(size / 16)`（16px→1、24/32px→2、40/48px→3…），外沿按 14/16 比例
  取整，正极居中 —— 所有矩形的边界都是**整数设备像素**，每条水平/垂直线都
  精确落在像素边界上，因此**代码里根本没有抗锯齿这一步**，也就不会有灰边；
- 内腔与电量块一律向内缩 **整数个线宽**，保证外框四周**等宽对称**
  （不会出现"左边 1px、右边 2px"的歪框）；
- 叠加图案（感叹号 / 横杠 / 斜杠）在各自区域内按格等分取整，永远贴合。

**第二层：交给 Windows 的 HICON 尺寸严格等于托盘尺寸（零缩放）**

这一层是**关键**。即使我们把 16×16 画得完全锐利，只要交给系统的是一个
被拉伸过的图标句柄，通知区域仍会把它缩回去，产生灰边 —— 早期版本正是栽在这里：

| 环节 | 结果 |
|---|---|
| pystray 默认用 `LoadImage(..., 0, 0, LR_DEFAULTSIZE)` 建图标 | `LR_DEFAULTSIZE` 取的是**大图标**度量 `SM_CXICON`=**32**，不是托盘用的 `SM_CXSMICON`=**16** |
| 于是 16×16 源图被**拉伸到 32×32** | 边缘冒出 44 种中间 alpha 值（255…8） |
| 通知区域再把它**缩回 16×16** 绘制 | 第二次插值，1 像素宽的外框被彻底糊掉 |

现在改用 `CreateIconIndirect` 从**精确 DIB** 直接包出 HICON：图标尺寸就是图像
尺寸，**代码路径里不存在缩放**。实测（`python tools/verify_hicon.py`）：

| 路径 | HICON 尺寸 | alpha 取值 | 是否有灰边 |
|---|---|---|---|
| pystray 原路径 | 32×32 ❌ | 46 种 | 有 |
| **本项目现在使用** | **16×16 ✅** | 仅 `[0, 255]` | **无** |

程序启动日志里会自己打印一行自证：

```
psbt.hicon: 托盘图标 HICON 精确创建成功：16×16（SM_CXSMICON=16，未走 pystray 的 LR_DEFAULTSIZE 路径）
```

另外，程序图标（.ico）内含 **16 / 20 / 24 / 32 / 40 / 48 / 64 / 128 / 256** 九个
尺寸，且**每个尺寸都是单独重绘的锐利位图**，不是从 256 缩放来的。

> **改了缩放比例需要重启吗？** 不需要。每次刷新都会重新读 `SM_CXSMICON`，
> 尺寸变了就按新尺寸重绘（日志里会记录 `托盘图标尺寸随 DPI 变化：16px → 20px`）。

### 显示优先级（多手柄时）

| 情况 | 图标显示 |
|---|---|
| 连接了 1 个手柄 | 显示该手柄的电量 |
| 连接了多个手柄 | 显示**电量最低**的那一个 |
| 没有手柄 | 外框 + 斜杠（"未激活"） |
| 手柄在但电量读不出 | 外框 + 横杠（"电量未知"，不显示过期的旧数值） |
| 充电中 | **与放电时同样显示真实电量**（充电状态见悬浮提示与菜单） |
| 低电量告警中 | 电量块转为**琥珀 / 红色**并闪烁约 8 秒 |

**所有状态一律使用同一个主色**（深色任务栏 → 纯白，浅色任务栏 → 主题深色），
整张图标**只有「透明」与「主色」两种像素**。"无手柄 / 电量未知"靠**图形**
（斜杠 / 横杠）区分，**不靠降低透明度** —— 半透明在深色任务栏上看起来就是发灰，
会破坏小尺寸下的锐利观感。这条已由单元测试锁定。

内部填充块单调映射电量，**不会出现电量下降反而填充变多的情况**。
各档位对应的电量块宽度严格为 0、1、2 … 10 格。

**两套风格，可随时切换**（右键菜单 → 图标风格）：

| 风格 | 特征 |
|---|---|
| **Windows 10**（默认） | 直角外框 —— 与用户给定的基准图逐像素一致 |
| **Windows 11** | 外框 / 电量块 / 正极**倒圆角**，与 Win11 任务栏观感一致 |

两种风格共用同一套几何（线宽、格数、正极位置完全相同），差别**只在圆角**。
圆角是**整数像素**的台阶裁剪，**不做抗锯齿** —— 所以切换风格后仍然只有
「透明」与「主色」两种像素，小尺寸下照样锐利。
选择会写入配置，重启后保持。

**图标颜色跟随系统亮暗主题**：深色任务栏画纯白图标、浅色任务栏画深色图标，
运行时切换主题后 **1 秒内**自动跟着换（见[已知问题](#已知问题与限制)说明）。

> **关于"过期缓存"**：手柄断开后，图标**立即**回到"无手柄"状态，
> 不会残留最后一次的电量数字误导用户。

悬停图标可看到详细提示，例如
`DualSense (PS5) · USB · 约 75%（等级 7/10）`。

> **注**：**充电时图标照样显示真实电量**，不再画满块 + 闪电 —— 闪电会盖住
> 电量条，看不出充到了多少，而"充了多少"才是托盘图标最该回答的问题。
> 充电状态（充电中 / 已充满）在悬浮提示与菜单文字里给出。
> 另外，充电中不会触发低电量告警（即使电量暂时偏低）。

## 低电量提醒

### 提醒阈值

默认三档：**低于 30% → 低于 20% → 低于 10%**。

因为电量每 10% 才跳变一档，这三个阈值实际对应：

| 阈值 | 实际含义 |
|---|---|
| 30% | 等级 ≤ 2 |
| 20% | 等级 ≤ 1 |
| 10% | 等级 0 |

### 提醒方式（四通道，见下节）

每次触发提醒时**同时**执行：

1. **托盘图标切换为告警图标并闪烁**约 8 秒；
2. **播放系统提示音**（`winsound.MessageBeep`）；
3. **弹出 Toast 气泡通知**（系统通知中心）；
4. **弹出置顶窗口**（仅在检测到通知被抑制时，见下节）。

### 防重复打扰（重点）

- **同一档位只提醒一次**。电量在 29%~31% 之间来回抖动**不会**反复弹窗。
- **进入更低档位时重新提醒**：`30 → 20 → 10` 恰好提醒 **3 次**，
  之后不再打扰，直到电量继续下降到下一档。
- 手柄**断开重连**后，会按当前电量重新判定（不会因为"已经提醒过"而漏报）。
- 多个手柄同时低电量时，提醒之间自动插入**至少 2 秒**间隔，
  避免多个弹窗叠在一起。

## 开机启动

菜单中勾选 **"开机启动"** 即可，取消勾选即关闭。

**采用的机制**：注册表键
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
下的值 `PSBatteryTray`。

选择理由：

- ✅ 这是**微软官方文档**（*Run and RunOnce Registry Keys*）推荐的
  自启动做法；
- ✅ 属于"当前用户"范围，**不需要管理员权限，不会弹 UAC**；
- ✅ 操作**幂等**，反复勾选不会产生重复项；
- ✅ 关闭时**只删除自己的那一项**，绝不触碰其它软件的自启动配置；
- ✅ 写入的是**当前 exe 的绝对路径**，程序被移动后重新开关一次即可修正
  （菜单会主动提示"路径指向旧版本"）。

**已知情况**：如果你在「**任务管理器 → 启动**」里把 `PSBatteryTray`
手动禁用了，注册表项还在但 Windows 不会自动运行它。程序能检测到这个状态
并**给出提示**，但**不会**擅自改写你的设置。

## Windows 10 通知限制与我们的对策

### 问题

Windows 10 的 **专注助手（免打扰）**、**游戏模式**、**演示模式** 会
**抑制 Toast 气泡通知**。如果程序只依赖 Toast，就会在最需要提醒的
时候（全屏游戏）恰恰提醒不到 —— 这正是低电量提醒最该发挥作用的场景。

### 我们的对策：四通道，永不依赖单一通道

| 通道 | 是否会被免打扰/游戏模式抑制 |
|---|---|
| ① 托盘图标告警 + 闪烁 | **不会** |
| ② 系统提示音 | **不会** |
| ③ Toast 气泡通知 | **可能会**（尽力而为） |
| ④ 自绘置顶弹窗 | **不会** |

程序会调用 `SHQueryUserNotificationState` **实时检测**当前是否处于
"通知会被抑制"的状态（全屏游戏、演示模式、专注助手等）。
**一旦检测到抑制，就自动启用第 ④ 通道（自绘置顶弹窗）来补偿被吃掉的
Toast。** 因此无论在什么状态下，**至少有一个通道能触达你**。

第 ④ 通道是**纯 Win32 自绘窗口**（不依赖 tkinter，不引入任何额外库），
使用 `WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`：
永远置顶、**不抢焦点、不出现在 Alt-Tab 里**，不会打断你的游戏操作。
窗口样式随系统深/浅主题自动切换，并按 DPI 缩放。

> 反过来说：如果你确实希望**完全安静**，可以在配置里把
> `enabled_alerts` 设为 `false`，或把 `alert_popup` 设为 `"never"`。

## 资源占用与稳定性

设计目标是"**轻量、长跑不崩、不泄漏**"。

| 项目 | 取值 | 说明 |
|---|---|---|
| 无手柄时设备枚举间隔 | **5 秒** | 空闲期几乎不占 CPU |
| 有手柄时设备枚举间隔 | **3 秒** | 用于发现热插拔 |
| 单手柄报告解析节流 | **最小间隔 0.25 秒**（≤4Hz） | 手柄可能以数百 Hz 推报告，全部解析纯属浪费 |
| 托盘图标刷新节流 | **最小间隔 0.15 秒**，且**必补尾部刷新** | 防止短时间大量 `Shell_NotifyIcon`；补尾部刷新是为了**不丢状态**（见下） |
| HID 读超时 | 1000 ms | 阻塞读 + 超时，不忙等 |
| 日志轮转 | 512 KB × 3 份 | 不会无限增长 |

**关于托盘刷新节流（一个已修复的真机 bug）**

刷新节流**不能简单地把超频的刷新丢掉**：检测层是**变化驱动**的（只有电量档位、
充电状态或连接状态真的变化时才回调一次），一旦丢掉，就再也没有下一次回调来补救，
图标会永久停在旧状态。

真机日志实测到的场景：手柄接入瞬间，「检测到手柄（电量未知）」与
「电量更新 percent=85」两条快照在**同一毫秒**先后到达，后者正好落在 150 ms
节流窗口内被丢弃 —— 表现为**"明明读到了电量，图标却一直显示电量未知"**，
直到电量下次变化才会自己好。现在的处理是：

1. 被节流的刷新会**排队一次尾部刷新**，窗口结束后用**最新**状态重绘；
2. 图标内容没变时**不重复推送**（画笔按状态缓存，同一状态返回同一个图像对象，
   用身份比较即可判断），因此尾部刷新几乎是零成本；
3. 看门狗每 30 秒用最新快照兜底重绘一次 —— 即使将来出现意料之外的丢失，
   也能在 30 秒内自愈。

**稳定性措施**：

- **每个手柄一个独立读取线程**，某一个手柄读取失败**不会影响**其它手柄，
  更不会让程序崩溃；
- 连续读失败超过阈值（默认 5 次）才判定该手柄不可读，并**自动重试**；
- 重复插拔**不会泄漏**线程或句柄：手柄移除时其读取线程被正确停止并回收；
- 所有后台线程均为 `daemon` 线程，程序退出即全部终止，不留残余进程；
- **单实例保护**：通过命名互斥体 `Global\PSBatteryTray.SingleInstance`
  保证同一时刻只有一个实例在跑，重复双击只会激活已有实例；
- 全局异常钩子：未捕获异常写入日志而非弹错误框，托盘程序不会"静默消失"。

### 排障利器：`--dump-hid`

如果你的手柄读数不符合预期，用它采集真实数据：

```bat
PSBatteryTray.exe --dump-hid 30
```

它会枚举所有 HID 设备、打印原始输入报告的十六进制，
并将结果保存到 `%APPDATA%\PSBatteryTray\logs\hid_dump_*.txt`。
拿着这份文件可以精确定位是设备未被识别、报告 ID 不符，还是字节偏移需要调整。

### 无需手柄也能验收：`--simulate`

```bat
PSBatteryTray.exe --simulate
```

内置时间线会依次模拟"接入手柄 → 电量下降 → 触发 30% / 20% / 10% 提醒
→ 断开重连"，用于直观验证图标、菜单、提醒全链路是否正常。

## 已知问题与限制

1. **电量只有约 11 档（每档 10%），不存在 1% 精度方案。**
   这是手柄固件与 HID 协议的物理上限，任何声称能读 1% 的工具都在伪造数据。

2. **DualShock 4 通过蓝牙连接时，可能只发送不含电量的"精简报告"。**
   程序会尝试切换为完整报告模式；失败时如实显示"电量未知"而不显示假数字。
   改用 USB 连接或使用 DualSense 可规避。

3. **托盘图标可能被折叠进"隐藏的图标"面板。**
   这是 Windows 10 的默认行为（非程序缺陷），手动拖到任务栏即可固定。

4. **部分连接方式尚未在真机上验证。**
   已在真机验证：**DualSense (PS5) USB**（含充电态）与 **DualShock 4 蓝牙**
   （含接入瞬间的报告序列）。未验证：DualSense 蓝牙、DS4 USB（协议路径相同，但未实测）。
   其余逻辑由 **96 项单元测试**、**模拟后端**与**可视化验证工具**覆盖。
   如与你的实际读数不符，用 `--dump-hid` 采集报告，对照 `parsers.py`
   顶部的协议注释即可定位偏移。

5. **异常电量值（电压/温度超范围、充电错误）显示为"电量未知/异常"，
   而不是 0%。** 这是刻意的设计 —— 避免误触发"电量耗尽"告警。

6. **图标在非整比例 DPI 下，电量块的单位宽度无法完全等分。**
   例如 125%（20px）时电量区 14 像素要分成 10 个单位。程序保证的是
   **每一条边都落在整数像素上**（所以绝不模糊），代价是相邻两档的宽度增量
   偶尔是 2 像素而不是 1 像素。所有 11 档在各尺寸下都仍然肉眼可区分，
   绝不出现"两档同宽"。

7. **图标清晰度与 pystray 内部实现绑定。**
   程序通过覆盖 pystray 的 `_assert_icon_handle` 来接管 HICON 创建。
   若未来 pystray 改掉该方法名，覆盖会静默失效、图标退回"被系统缩放"的老路。
   启动时已加自检：一旦失效会在日志里告警
   （`当前 pystray ... 没有 _assert_icon_handle`），不会悄悄退化。

8. **专注助手设为"仅优先级通知"时，`SHQueryUserNotificationState`
   无法区分。** 程序在这种情况下的策略是"宁可多提醒"：
   检测到任何抑制状态都会启用置顶弹窗通道。如果你觉得打扰，
   可在配置中把 `alert_popup` 设为 `"never"`。

9. **程序被移动到其它目录后，开机启动项会指向旧路径。**
   菜单会提示"路径指向旧版本"，关闭再重新勾选一次即可修正。

10. **未做代码签名。** Windows SmartScreen 首次运行可能提示
    "未知发布者"，点击"更多信息 → 仍要运行"即可。
    （代码签名证书需付费购买，个人项目未包含。）

11. **主题跟随靠 1 秒一次的注册表轮询，而不是系统事件。**
    切换亮暗后最多 1 秒跟随（实测远快于原来的 30 秒），但严格说仍是轮询：
    读的是 `HKCU\...\Themes\Personalize` 下的一个 DWORD，开销在微秒级，
    对 CPU 无可见影响。若要做到零延迟，需要承接 `WM_SETTINGCHANGE`
    （`ImmersiveColorSet`）或 `RegNotifyChangeKeyValue`，属于后续可优化项。

12. **图标风格只影响托盘图标本身。** exe 的文件图标（资源管理器里看到的那个）
    仍是固定的蓝图风格，不随此开关变化。

## 版本历史

### 1.3（当前）

- **新增 Windows 11 圆角图标风格**，右键菜单 →「图标风格」可在
  Windows 10（直角）/ Windows 11（圆角）之间随时切换，无需重启，选择写入配置。
  两套风格**共用同一套几何**，差别只在圆角；圆角用整数像素台阶实现，
  **不做抗锯齿**，所以 alpha 依旧只有 0 / 255，小尺寸下照样锐利。
- **修复：运行时切换系统亮暗主题，图标不跟随。** 根因是主题探测间隔长达
  30 秒（且与看门狗同频），用户在设置里切换后最长要等半分钟才变色，
  体感等于"不跟随"。现在主题复查独立成 1 秒一次（读一个 HKCU 的 DWORD，
  微秒级开销），托盘重绘 / 菜单重建等重活仍是 30 秒一轮。
- 单元测试 84 → 96 项。

### 1.2

- **修复：DualShock 4 用蓝牙接入时会先误报一次「约 5%」。**
  真机上接入瞬间会先收到一条 64 字节的报告 `0x01`，被蓝牙栈补齐后长度"合格"，
  于是被当成 USB 完整报告去读下标 30 —— 那里是填充的 `0x00`，解析成「0 档 / 约 5%」，
  并**误触发一次低电量提醒**，十几秒后才被真正的 `0x11` 报告纠正。
  根因是**只看报告 ID、没用连接方式区分**——而 `0x01` 在 USB 上是完整报告、
  在蓝牙上却是精简报告（协议里没有电量字段）。现已按内核驱动的判据
  （`hdev->bus`）改为**报告 ID + 连接方式**共同判定：蓝牙上的 `0x01` 一律按
  精简报告处理（等级未知），交给既有机制去尝试切换完整模式。
  回归测试用了真机日志里抓到的原始报告字节。

### 1.1.0

- **充电时图标改为显示真实电量** —— 不再画满块 + 抠闪电（闪电会盖住电量条，
  看不出充到多少）；充电状态改由悬浮提示与菜单文字表达，充电中也不再触发低电量告警。
- **修复：读到电量但图标停在"电量未知"** —— 托盘刷新节流会丢弃超频刷新，而检测层
  是变化驱动的，被丢掉就再没有回调补救。改为排队**尾部刷新**（+ 状态未变不重复推送
  + 看门狗 30 秒兜底），该竞态在真机上是稳定复现的。
- **托盘图标清晰度修复** —— 改用 `CreateIconIndirect` 生成**精确尺寸** HICON，
  消除 pystray `LR_DEFAULTSIZE` 把图标放大到 32×32 再由通知区域缩回 16×16 造成的
  灰边/发虚；同时按目标像素网格重算几何，彻底不做缩放。
- 图标按参考图重绘：外框 → 一圈等宽留白 → 内部电量块；四种状态统一纯主色，
  整张图标只有「透明」与「主色」两种像素。

### 1.0.0

- 首个版本：托盘实时显示电量（多手柄取最低）、30% / 20% / 10% 三档低电量多通道
  提醒、开机启动开关、单文件免安装 exe。
